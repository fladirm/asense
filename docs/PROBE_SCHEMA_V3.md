# ASense probe schema 3

Status: implementation contract for ASense v0.3.0. This document and the
fixtures under `tests/fixtures/probe-v3/` were frozen before implementation;
evidence-backed corrections to HID bus/interface/usage authority remain part
of the same schema-3 contract and are covered by strict reopen tests.

## Purpose

`asense probe` is a bounded, read-only compatibility report. Schema 3 must let
maintainers distinguish a missing interface, an unreadable interface, an
unknown but successfully read value, and a decoded value without asking users
for journals, raw ACPI tables or a privileged command console.

The report is evidence, not a support claim. A discovered transport or a
successful firmware readback does not prove a physical CPU/GPU power, fan or
lighting effect.

`asense probe --summary` performs the same default passive collection and
prints only a bounded human-readable derivative. It is not a second schema and
does not replace the JSON attachment. The complete excluded-identity,
raw-allowance and same-state support workflow is maintained in
[`PROBE_PRIVACY.md`](PROBE_PRIVACY.md).

## Normative invariants

1. The default command performs no mutation. It may negotiate the existing
   typed daemon protocol, use a dedicated bounded passive diagnostic command,
   read bounded sysfs/procfs files and issue passive HID feature reads. It
   never calls the historical general `CAPS` path, sends an ENEK A2 selector
   or sends an A4 lighting report.
2. An optional extended HID mode, if implemented, is a different explicit CLI
   action. It may send only the typed two-byte `A2,target` selector needed for
   an A3 read. Every attempted selector is recorded. It never sends A4.
3. Report schema and daemon protocol are independent. Schema 3 does not by
   itself change `HELLO 2`.
4. Every production report is encoded from `serde` structs/enums with unknown
   fields denied on reopen. There is no hand-built untyped JSON authority.
5. Top-level field order is the order below. Arrays use a documented stable
   sort key. Pretty JSON ends with one newline.
6. All strings, arrays, payloads and the complete output are bounded before
   allocation or serialization.
7. Error records contain a stable stage/class and optional errno, never an
   absolute path or an unbounded operating-system error string.
8. Raw value retention is allow-listed. Anything not explicitly listed in
   the privacy manifest is decoded, hashed or omitted.
9. There is no automatic upload, persistent report identifier or implicit
   collection of journals, serials, UUIDs, host/user/network identity, boot ID
   or raw ACPI tables.

## Schema-2 inventory and information loss

Schema 2 is generated by `src/probe.rs` from these sources:

| JSON field | Source | Current collapse |
| --- | --- | --- |
| `schema` | compile-time constant `2` | none |
| `asense` | Cargo package version | build commit and daemon version absent |
| `dmi.vendor/product/board/bios` | four allow-listed DMI sysfs text files | missing, open, read, invalid UTF-8 and empty all become `null`; UTF-8 is lossy |
| `profiles.backend` | first discovered kernel profile, else Gaming-WMI | all discovery failures become `null` |
| `profiles.choices_source` | backend-derived label | absent backend and failed discovery both become `null` |
| `profiles.choices[]` | live choices read | read/decode failure becomes an empty list through `unwrap_or_default` |
| `profiles.current` | live profile read | absent, I/O failure and invalid/unknown state become `null` |
| `hwmon.name` | selected Acer hwmon `name` | absent and read failure become `null` |
| `hwmon.fan_backend` | independent hardware capability discovery | absent, unreadable behavior and incomplete nodes become `null` |
| `hwmon.fan_inputs[]` | typed RPM capability snapshot | a failed channel read is represented only as `rpm:null`; source/error is absent |
| `hwmon.temps[]` | `tempN_input` plus optional label | failed channels disappear; missing labels are synthesized |
| `hwmon.pwm_nodes[]` | names matching exact `pwmN[_enable]` grammar | existence only; readability and values are not reported |
| `wmi.known_guids[]` | three allow-listed WMI GUID directory matches | instance/driver/group/read status absent |
| `wmi.gaming_fan/profile` | selected backend equality | transport present but rejected during discovery becomes `false` |
| remaining `wmi.*` booleans | attribute path existence | exposed, readable, decoded and validation-error states are conflated |
| `lighting[]` | daemon `CAPS` response | daemon absence, timeout, protocol error and command error all become `[]`; on ENEK machines `CAPS` currently runs full controller discovery, whose A2→A3 capability query is a selector write |
| `hid[]` identity | allow-listed I2C `0cf2:5130` uevent | malformed/unreadable candidates disappear |
| `hid[].targets[]` | passive A1 HID feature read | open/ioctl/length/decode errors all become `targets_unqueried:true` |
| `hid[].targets[].*` | A1 IDs only | zones/modes/state deliberately remain `null` because A3 needs A2 |

Schema 3 removes these collapses. It does not weaken the existing setters or
claim support for an undecoded value.

The new probe must not fall back to `CAPS`. It negotiates `HELLO 2` and asks
for one additive typed passive diagnostic snapshot. An old daemon that rejects
that command is reported as incompatible/unsupported while local passive
collection continues. This prevents an old-daemon compatibility fallback from
silently reintroducing the ENEK A2 selector write.

## Collection authority

The collector is deliberately split instead of giving one layer generic
hardware access:

| Section | Authority |
| --- | --- |
| provenance, DMI, kernel, OS, power | unprivileged CLI, fixed allow-listed files/syscalls |
| module/WMI/hwmon ownership | unprivileged CLI, fixed allow-listed sysfs identities |
| profile transport/current/raw/choices | one typed daemon passive diagnostic; bounded kernel diagnostics where normal profile sysfs cannot represent an unknown byte |
| fan control discovery and per-read failures | typed daemon passive diagnostic; read-only hwmon telemetry may be cross-checked locally |
| platform expected/exposed/read/decode/error/raw | typed daemon passive diagnostic backed only by fixed kernel fields |
| zoned-WMI lighting capability | passive typed diagnostic/local fixed sysfs contract |
| ENEK identity/descriptor/A1 | typed root daemon diagnostic; exact allow-listed HID identity, descriptor read and passive A1 GET_FEATURE only |
| ENEK A2/A3 | explicit extended mode only |
| EC-HID `1025:174b` | typed root daemon diagnostic; exact HID-over-I2C detection/descriptor hash only |

The bounded daemon command returns typed evidence, never an arbitrary path,
WMI method, HID report or EC offset. ENEK targets discovered only by A1 remain
in `hid[]`; they do not become semantic `lighting[]` devices until a matching
versioned A3 codec and evidence cohort exist.

## Common evidence types

Read-only observations use one of these exact tagged variants:

```json
{ "status": "value", "source": "stable-source-id", "value": 1 }
{ "status": "absent", "source": "stable-source-id", "reason": "not-exposed" }
{
  "status": "error",
  "source": "stable-source-id",
  "error": { "stage": "read", "class": "permission-denied", "errno": 13 }
}
```

Allowed error stages are `discover`, `open`, `read`, `decode`, `protocol` and
`verify`. Allowed classes are `not-found`, `permission-denied`, `io`,
`timeout`, `invalid-value`, `incompatible`, `unsupported` and `oversize`.
`errno` is either a non-negative Linux errno or `null`. A report never embeds
the source path or raw error message.

Allowed absence reasons are `not-exposed`, `not-installed`, `not-applicable`,
`daemon-unavailable` and `incomplete-control-interface`. They are enums, not
free-form messages.

Profile current state is a separate tagged type:

```json
{
  "status": "known",
  "source": "gaming-wmi-profile",
  "raw": { "encoding": "u8-hex", "bytes": 1, "value": "04" },
  "profile": "performance"
}
{
  "status": "unknown",
  "source": "gaming-wmi-profile",
  "raw": { "encoding": "u8-hex", "bytes": 1, "value": "02" }
}
```

`unknown` is successful evidence and is never transformed into a selectable
profile. `absent` and `error` use the common reason/error shapes.

## Top-level contract

The exact top-level order is:

```text
schema
provenance
machine
power
drivers
profile
fans
platform
lighting
hid
privacy
```

### `provenance`

- `report`: exact token `asense-probe`;
- `asense_version`: Cargo version;
- `build_commit`: lowercase 40-hex commit for release artifacts, otherwise
  `null`; never a build path;
- `captured_at_utc`: RFC 3339 UTC timestamp;
- `capture_duration_ms`: monotonic duration from the first to last collected
  observation, allowing power/profile evidence to be judged as one bounded
  snapshot;
- `mode`: `passive` or `extended-hid`;
- `daemon`: common observation whose value contains exact daemon version and
  negotiated protocol.

### `machine`

- `dmi.vendor/product/board/bios`: four independent common observations;
- `kernel.release/architecture`: independent observations from `uname`;
- `os.id/version_id`: allow-listed `/etc/os-release` keys only.

No other DMI or OS identity is collected.

### `power`

- `ac[]`: stable ordinal, type and an independent `online` observation;
- `batteries[]`: stable ordinal plus `present`, `status` and
  `capacity_percent` observations;
- no manufacturer, model, serial or device path.

Arrays are sorted by power-supply type and kernel entry name before names are
discarded and ordinals assigned. At most eight AC and eight battery entries
are retained.

### `drivers`

- `modules[]`: only allow-listed `acer_wmi` and `asense_rgb`, with loaded and
  bounded version observations;
- `wmi[]`: only the three ASense-known GUIDs, number of instances, an explicit
  driver-owner observation and known exported group names;
- `hwmon_owner`: common observation with a bounded driver/module token.

GUID instances are sorted numerically; exported groups are from a fixed enum,
not arbitrary directory names. The enum includes the fixed admin-read-only
`asense_diagnostics` group separately from every production control group.

### `profile`

- `transport`: `present`, `absent` or `error`; a present value names `kernel`
  or `gaming-wmi` and a stable source ID;
- `current`: `known`, `unknown`, `absent` or `error`;
- `choices`: common observation over bounded typed choices. Every choice has
  the daemon/sysfs `command` token, semantic `profile`, optional one-byte
  `transport_raw` evidence and `selectable`; command and firmware coordinates
  are never conflated;
- `firmware_supported_bitmap`: a separate advisory observation. If present,
  it retains one bounded byte and is labeled `firmware-advisory`; no bit is
  assigned a semantic profile without a separately pinned decoder, and it
  never enables a choice by itself;
- `physical_effect`: always `unverified` in a probe report unless a separate
  externally executed physical receipt is referenced by release evidence.

Canonical Gaming-WMI mappings remain `00=quiet`, `01=balanced`,
`04=performance`, `05=turbo`, `06=eco`. Raw `02` is unknown and never appears
in choices.

### `fans`

- `control`: independent `present`, `absent` or `error` state; a present value
  names the backend and exact Auto/Manual/Maximum booleans;
- `rpm[]`: independently retained channels with typed read observations;
- `pwm[]`: passively observed channel/setpoint/mode reads, never writes. Each
  channel carries `setpoint_unit:"pwm255"` for kernel `0..255` values or
  `setpoint_unit:"percent"` for Gaming-WMI `0..100` values; mode `0` is
  represented as `maximum`, not the unrelated generic-hwmon word `disabled`;
- `temperatures[]`: independently read bounded telemetry channels.

Control without RPM and RPM without control are both valid reports. Arrays are
sorted by numeric channel and capped at 32 entries.

### `platform`

- `transport`: independent presence/error evidence;
- `fields[]`: exactly these names in this order: `battery-limit`,
  `battery-calibration`, `usb-off-charging`, `keyboard-timeout`, `boot-sound`,
  `lcd-override`, `rear-logo`;
- each field records `expected`, `exposed`, stable `source` and a `read`
  observation;
- decoded values are tagged `bool`, `usb-threshold` or `rear-logo`;
- validation failure is an error, not `unsupported`; an allow-listed bounded
  scalar may accompany the error.

WMI rear logo is not an ENEK cover logo and no fallback connects them.

### `lighting`

Typed daemon capabilities retain ID, backend, target, zones, modes and
readability. Each item has `authority:"transport-capability"`; the probe does
not claim a physical effect. `state_readable` is true only when the fixed
`power`, `effect` and `zones` getters all return non-empty state during the
same capture. Items are sorted by ID and capped at 32.

### `hid`

Every retained device has:

- `role`: `enek5130-lighting` or `acer-ec-hid-power-candidate`;
- sanitized identity: bus, VID, PID and an allow-listed static device name;
  USB interface is `null` for HID-over-I2C and usage page/usage are present
  together only when uniquely derived from the descriptor's application
  collection; arbitrary HID names are omitted;
- driver observation;
- descriptor observation containing byte length, SHA-256 and bounded feature
  report geometry, but not raw descriptor bytes;
- for ENEK only, passive A1 observation with requested/returned lengths,
  bounded payload and sorted unique target IDs;
- `extended`: whether requested, the exact A2 selector receipts, and A3 read
  observations. Passive reports have no selector receipts.

Detecting `1025:174b` establishes only a candidate transport. No performance
mode is sent and no physical support is claimed.

### `privacy`

The report repeats its own collection policy:

- `automatic_upload:false`;
- `persistent_report_id:false`;
- `default_mutations:[]`;
- `extended_mutations`: attempted A2 selectors only;
- exact excluded identifier classes;
- exact bounded raw allow-list and limits.

## Bounds

```text
complete pretty JSON                     262144 bytes
any ordinary text/token                  96 bytes UTF-8
profile command token                    48 ASCII bytes
arrays                                   32 items unless narrower above
known WMI GUIDs                           3
platform fields                           7
HID report descriptor                    4096 bytes input; hash/geometry output
descriptor geometry                      64 entries
profile WMI raw                           1 byte
firmware supported-profile bitmap         1 byte
platform raw scalar                       8 bytes
ENEK A1/A3 payload                       64 bytes
errno                                    non-negative i32 or null
```

Oversized input produces a typed `oversize` error; it is never silently
truncated into apparently valid evidence.

## Raw allow-list

Only these paths may contain raw material:

| Path | Encoding | Maximum | Purpose |
| --- | --- | --- | --- |
| `profile.current.raw` | one-byte hex or bounded ASCII token | 48 bytes | preserve unknown profile evidence |
| `profile.choices.value[].transport_raw` | one-byte hex | 1 byte | retain a known Gaming-WMI coordinate separately from its command token |
| `profile.firmware_supported_bitmap.value.raw` | one-byte hex | 1 byte | advisory firmware bitmap evidence |
| `platform.fields[].read.error.raw` | scalar hex | 8 bytes | preserve exact decoder failure |
| `hid[].a1.value.payload` | hex | 64 bytes | passive ENEK target report |
| `hid[].extended.a3[].read.value.payload` | hex | 64 bytes | explicitly selected A3 evidence |

HID descriptors are SHA-256 plus decoded geometry only. Raw ACPI/WMI buffers,
arbitrary sysfs content and arbitrary USB/HID reports are forbidden.

## Privacy deny-list

Collectors and fixtures must reject or omit:

```text
DMI/chassis/product/board serials
all UUIDs
hostname and machine-id
user/login/home path
MAC, IP, SSID and other network identity
boot ID
storage serial/WWN
USB/HID serial and unique physical path
journal/dmesg content
raw ACPI tables
absolute /sys, /dev or /proc paths
arbitrary environment variables
persistent random report identifiers
```

The compatibility report remains user-reviewed and manually attached.

## Golden cases

The fixtures freeze these semantics before implementation:

- `known.json`: known kernel profile, fan control with RPM, decoded platform
  values and no HID device;
- `unknown-error.json`: Gaming-WMI raw `02` remains unknown, control exists
  without RPM, a platform validation failure retains only an eight-byte raw
  scalar, passive ENEK A1 reports targets `21/65/83`, and `1025:174b` is only
  a detected power candidate;
- `profile-read-error.json`: the profile transport and known choices remain
  present while reading the current state fails with a typed errno;
- `absent-rpm-only.json`: profile/control/platform transports are absent while
  independent RPM remains readable.

All fixtures are passive (`mode:"passive"`), contain no A2 receipt and have
empty `default_mutations` and `extended_mutations`.
